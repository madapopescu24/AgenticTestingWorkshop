Read automatically every Claude Code session in this repo. Apply all rules below.

This course reuses the authoring framework from the **Agentic Practice Workshop**
(https://github.com/uipath-practice/AgenticPracticeCourse). The `Master/` rules,

## Project purpose

A GitHub Pages–hosted MkDocs site teaching technical clients & partners **UiPath
Agentic Testing with coding agents**: planning tests in **Test Manager**, automating
them in **Studio**, executing them through **Orchestrator**, and reporting on them,
using **Autopilot for Testers** and **Autopilot for Developers** (in Studio and Test
Manager) side by side with a coding agent that uses the `uip` CLI and UiPath skills
(`uipath-test`, `uipath-rpa`, `uipath-platform`). The session opens with Autopilot in
Studio generating the requirements (one per design step) from the design document;
Autopilot in Test Manager then generates the test cases. Audience is technical and knows the
UiPath platform but is new to AI / coding agents.

The hands-on scenario is the design document **E2E UiBank Online
Banking** (`E2E UiBank Online Banking.docx`) against `uibank.uipath.com`. It is NOT tested as one E2E
test case: each of its eight steps becomes one requirement (named after the step title)
and one independent test case (named after the step, Studio files `T0_…` to `T7_…`)
that sets up its own data in Given. Keep variable names, steps, and expected results
consistent with that document.

The workshop agenda is fixed (see `docs/agenda.md`), 9:00–17:00: Welcome; 1. Intro + Theoretical Aspects;
2. Hands-on — Setup (first: create a new project in Test Manager, e.g. name `{YourName}_UIB_Test`,
a unique prefix `{YourPrefix}` of 3–5 characters, never a shared `UIB`; then a new test automation project in Studio, connected to it), Requirements (Autopilot in Studio creates them from the .docx,
discuss in Test Manager, evaluate / improve / re-evaluate with Autopilot in Test
Manager), Test Cases (Autopilot in Test Manager generates them; Login implemented
manually; next one generated by Autopilot in Studio or Codex; Run Autonomously demo;
a few more), Executions tab, Test Sets (publish the testing project to the tenant
feed first; Autopilot in Studio creates them; run; look into executions), Next Steps. Requirements, Test Cases, Executions, and Test Sets
are their own top-level tabs (`requirements.md`, `test-cases.md`, `executions.md`,
`test-sets.md`); the Testing Setup tab (`agentic-testing-hands-on.md`) keeps the intro, design document, Setup,
Next Steps, and Gotchas. Keep them in that order. The CLI cheat sheet lives on the Resources tab (`resources.md`).
After Next Steps: 3. SAP Testing (1 h, no tab of its own), Q&A, and Feedback.
The agenda says its timings are approximate and can be adapted, including breaks.
Topic names below the top level are not numbered (no 2.1, 2.1.1, …).

**Scope is deliberately narrow.** Out of scope (separate courses): building agents and
Maestro orchestrations, Document Understanding / IXP. The click-by-click Test Manager
and Studio course is the Test Cloud & Agentic Testing ILT Guide
(https://meera-uipath.github.io/software-testing-ilt-guide); link to it rather than
duplicating it.

## What is DIFFERENT from the base framework

### 1. Knowledge base (SSOT) — separate and private
- The validated knowledge base lives **outside this repo** at `../knowledge-base/`.
- It is the single source of truth for product facts; lessons are generated FROM it.
- **NEVER copy KB content into this repo or commit it.** It may contain internal
  material. `knowledge-base/` is gitignored here as a safety net.
- When generating a lesson, read the relevant `../knowledge-base/concepts/**` files
  for accurate, current product facts, then write the lesson into `docs/`.

### 2. Two lesson-generation paths (both valid)
- **Screenshot path** (unchanged from base framework): for Studio Web / browser UI
  steps where participants need click-by-click instructions. Use `/new-lesson` with
  screenshots → metadata → page.
- **CLI / KB path** (new): for terminal/`uip` CLI/code steps, generate from KB
  concept files + captured CLI transcripts/commands rather than screenshots.
- A single lesson may mix both (e.g., CLI setup + a Studio Web screenshot).

### 3. Environment is configurable (not hardcoded)
- `main.py` (mkdocs-macros) provides `{{ training_url }}`, `{{ training_authority }}`,
  `{{ training_org }}`, `{{ training_tenant }}`, `{{ training_folder }}`, and
  `{{ env_label }}`, switched by the `COURSE_ENV` variable (`staging` | `prod`).
- **Always use these variables in the training-environment callout** — never hardcode
  a URL or tenant. Values:
  - prod: cloud.uipath.com/tpenlabs, tenant `AgenticTestingWorkshop` — **the
    participant environment**. CI deploys with `COURSE_ENV=prod`.
  - staging: staging.uipath.com/partnersuccess, tenant `MadalinaTest` — kept as a
    fallback.
- Author, preview, and release with `COURSE_ENV=prod` (also the default).

## Quick reference (always in context)

- **Voice:** second person, short sentences, conversational. Avoid "leverage",
  "utilize", "seamlessly", "In this section we will", "Please note that".
- **Platform names** bold on first use: **Agent Builder**, **Maestro**, **Studio Web**,
  **Orchestrator**, **Action Center**, **ServiceNow**, **Integration Service**.
  Coding-agent terms: **Claude Code**, the **`uip` CLI**, **UiPath skills**.
  Testing terms: **Test Cloud**, **Test Manager**, **Autopilot for Testers**, **Test Explorer**.
- **Code blocks:** always fenced with a language identifier (use `bash` for CLI).
- **Visual style (light theme, inspired by the UiPath Partner Day deck):** prefer the
  components in `docs/stylesheets/extra.css` over tables — `timeline` (time plans),
  `circles` (numbered steps/levels), `feature-grid` (concepts, options), `fix-grid`
  (symptom → cause → fix), `link-grid` (links), `vs` (comparisons). Keep tables only for
  lookup data (variables, CLI cheat sheet). Each page starts with an orange `eyebrow`
  label, an emoji in every heading, and a `time-badge` for durations.
- **Drafts** are not added to `mkdocs.yml` nav; use `mkdocs.local.yml` to preview,
  `/publish-exercise` to promote.
- **Never delete** explanatory content; rephrase. Archive, don't delete, retired pages.
- Run `COURSE_ENV=prod mkdocs build` to verify before committing.
